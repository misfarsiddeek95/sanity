# Scentify Fragrances: Next.js storefront

Next.js 16 (App Router, React 19, Tailwind 4, TypeScript strict). Built for a Node server / VPS.

## Quick start

```bash
npm install
npm run dev          # http://localhost:3000
npm run typecheck && npm run lint
npm run build        # production build (standalone output)
```

## Deploy on a VPS (Node 20.9+)

```bash
npm ci && npm run build
# the standalone server needs the static assets next to it:
cp -r .next/static .next/standalone/.next/static
cp -r public .next/standalone/public
cp .env.example .env.production   # edit values
cd .next/standalone && HOSTNAME=127.0.0.1 PORT=3000 node server.js
```

* `deploy/ecosystem.config.cjs`: pm2 process file (keeps the app running and restarts it).
* `deploy/nginx.conf`: TLS, per-IP request limits, connection caps and the client-IP headers the app trusts.
* Put **Cloudflare** (free plan is enough) in front for volumetric DDoS, bot management and caching.

## Project structure

```
src/
  app/            routes (App Router): one folder per URL, metadata + JSON-LD per route
    api/lead/     validated, rate-limited lead endpoint
  views/          page components (client components, shared UI state)
  components/     Layout, shop, ui kit (Photo, Container, Button …), consent, lead forms
  data/           catalogue, guides, FAQ, site config (single source of truth)
  lib/            seo, schema (JSON-LD), pricing, analytics, consent, router adapter
  lib/server/     rate limiter, request guard, lead validation
  proxy.ts        request gatekeeper (bots, probes, host, method, rate limit)
public/           photos, brand assets, manifest, llms.txt, opensearch.xml
```

SEO files are generated by routes, not scripts: `/sitemap.xml`, `/robots.txt`, `/feed.xml`, `/llms-full.txt` (and the static `/llms.txt`).

## Security layer

| Threat | Protection |
| --- | --- |
| DDoS / flooding | nginx `limit_req` + `limit_conn` (edge), in-app sliding-window limiter per IP (`proxy.ts`), body size caps, URL-length cap. Use Cloudflare for volumetric attacks. |
| Spam / bot submissions | Same-origin + custom header check, honeypot, time-trap, per-IP and per-contact limits, link / spam-phrase screening, strict schema validation (zod). |
| Unauthorised comments and submissions | The site has no comments or user-generated pages. The only write endpoint is `/api/lead`, and it accepts nothing outside the schema. |
| Backlink / SEO spam | No indexable user content, search and query URLs are `noindex` + disallowed in robots.txt, oversized query strings are rejected, known backlink crawlers and scrapers are blocked, `host` is allow-listed (no duplicate domains). |
| XSS | React escaping, JSON-LD escaped (`<` → `<`), CSP (`default-src 'self'`, no `object-src`, `frame-ancestors 'none'`), input sanitiser on the server. |
| CSRF | The API is cookie-less; every POST must be same-origin (`Origin`/`Sec-Fetch-Site`) with a custom header and JSON content type. |
| API abuse | 20 req/min per IP on `/api`, 5 lead submissions per 10 min per IP, one per contact per hour. |
| Scanners / probes | Exploit paths (`/wp-admin`, `.env`, `.git`, `*.php` …) return 404 and 5 hits in 10 min bans the IP for an hour. |
| Clickjacking, sniffing, downgrade | `X-Frame-Options`, `frame-ancestors`, `nosniff`, HSTS (preload), Referrer-Policy, Permissions-Policy, COOP. |
| Secrets / info leaks | `X-Powered-By` removed, no source maps, `.env*` ignored, no secrets in the client bundle. |

Limits to know about:

* The in-memory limiter is per process. Run one instance, or move the limiter to Redis before scaling out.
* The CSP allows inline scripts (Next.js bootstrap). A per-request nonce would make every page dynamic and lose static generation.
* Sign-in, cart and orders are still **front-end only** (stored in the visitor's browser). Passwords are hashed with PBKDF2 and never stored in plain text, but real accounts need a server-side auth provider.

## Connect forms to your inbox / CRM

Set `LEAD_WEBHOOK_URL`. Every accepted lead (newsletter, offer pop-up, gift finder, back-in-stock) is forwarded as JSON.
